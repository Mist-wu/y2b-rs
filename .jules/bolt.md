## 2024-05-19 - SQLite Correlated Subquery N+1
**Learning:** Correlated subqueries in SQLite `ORDER BY` clauses (e.g., `ORDER BY COALESCE((SELECT CASE ... FROM channels WHERE channels.id=jobs.channel_id),0) DESC`) cause severe N+1 performance bottlenecks. While the query planner might optimize some subqueries, evaluating a subquery per row for ordering before LIMIT is applied is extremely slow compared to a `LEFT JOIN`. Also, derived tables without aliases (`SELECT * FROM (SELECT ... )`) will lose table prefixes, causing `ambiguous column name` errors if used with `LEFT JOIN` and non-prefixed `SELECT` lists.
**Action:** Replace correlated subqueries in `ORDER BY` with `LEFT JOIN`s. Ensure that shared column selection constants (like `JOB_COLUMNS`) are updated with explicit table prefixes (`table.col`) to prevent "ambiguous column" errors when joins are introduced, rather than trying to wrap the query in an unaliased derived table.
